# 明棋 AI 修复版训练与评测

这份说明用于在本机继续双人明棋训练。v4 修复了已确认的训练、统计和效率问题，并提供独立的训练模型、出棋模型和冠军模型。模型达到高手或顶尖水平，需要在未参与调参的布局、强启发式和真人对局中证明；训练损失下降不会自动授予这个结论。

## 运行入口

在项目目录运行：

```powershell
cd .
.\run_open_v4.ps1 -ThroughIteration 2
```

重复同一命令会读取完整检查点。提高 `ThroughIteration` 即可继续，不需要安排固定的每日时段。入口使用已有 `python`，不安装或改变环境。

主配置是 `config/open_junqi_v4_repaired.json`，输出为 `runs/open_junqi_v4_repaired`。调参时使用新的配置和运行目录；系统会校验配置、训练源码、编译模块、布局清单和教师二进制，阻止混用不同实验。

已完成的两轮小规模验证保存在 `runs/open_junqi_v4_repair_pilot`，对应 `config/open_junqi_v4_repair_pilot.json`。它的第三轮才安排开发门禁，前两轮用于验证更新积累和完整恢复。两项显式源码契约迁移分别记录在该目录的 `migrations/global_phase_counter.json` 与 `migrations/cuda_graph_inference.json`，用于全局训练阶段计数和已验证等价的推理加速；模型、优化器与随机状态未被重写。两轮试跑之前仍按每轮重置的阶段执行，迁移后的后续训练按全局阶段执行。

```powershell
.\run_open_v4.ps1 -Config config/open_junqi_v4_repair_pilot.json -ThroughIteration 3
```

## 三种模型的用途

`CURRENT.json` 是已提交状态的入口，分别指向 `learner`、`actor`、`champion` 检查点，并记录文件摘要与模型摘要。

- 训练模型保留通过数值与 KL 约束的更新，继续积累优化器状态。对局门禁未通过不会抹掉这一轮学习。
- 出棋模型只在开发对局的非劣性门禁和教师对照通过后更新，因此自我对弈可以继续使用稳定的旧出棋模型。
- 冠军必须在完整开发集合上，对当前冠军取得置信区间下界超过 50% 的得分，并满足教师对照与最少布局家族数。

新运行中的初始冠军表示该运行的初始比较基线。它不是“顶尖 AI”的认证。v3 的冻结冠军仍保留在原目录。

每个检查点包含模型、优化器、常数学习率调度状态、有效和尝试更新计数、配置、随机状态、来源与谱系。先写完整检查点和报告，最后原子更新 `CURRENT.json`。中断后的数据分片按摘要复用。

## 布局和数据

`config/layouts/open_v4/manifest.json` 固定了 64 个训练布局家族、128 个开发家族和 256 个最终评测家族。一个布局及其水平镜像属于同一个家族。三个集合互不重叠，最终集合不能用于训练、调参或晋级。

训练固定这批家族，并在其中生成双方布局不同、整盘镜像的合法组合。双方颜色对应的两局归入同一个轨迹家族，内部验证整组留出。开发集合使用互不共享布局的成对家族，从开局和教师对弈前缀构造状态，并保留完整动作历史。

数据来源包括教师自我对弈、教师对出棋模型，以及网络自我对弈。默认教师是冻结的 082 与 084 原生引擎。教师决策保存为明确标注来源的稀疏单次动作投票；网络数据保存实际搜索访问次数。不会给未搜索动作编造 Q 值。

Value 标签取真实终局，输、和、赢分别是三个类别。完整规则始终由原生引擎判定：重复三次、无吃子 200 ply、总长 1000 ply 的边界不变。训练不使用 material 奖励塑形，也不把循环和局改成输棋。

内部验证用于观察学习，不承担“泛化已解决”的证明。开发对局按布局家族聚类并交换双方颜色；最终集合在停止调参后再独立验证。

## 更新与显存

默认逻辑批量 256，分为 64 条样本的小批量累积梯度。两次 Policy 更新之后安排一次 Value 更新，阶段按全局尝试更新数延续，跨轮或恢复时不会重新从 Policy 开始。

Value 分支使用训练样本上的冻结 Policy 参照。第一步的参照梯度可以为零，因此还必须检查更新后的 KL；超限时恢复模型、优化器和随机状态，降低学习率重试，最多五次。状态平均和家族平均 KL 都受 0.001 的限制。仍失败则只拒绝该步，并记录有效更新数。

默认保留原 192 通道、10 个残差块的网络。`config/open_junqi_v4_compact.json` 提供 128 通道、6 个残差块的独立教师启动实验；它需要重新训练，不能直接载入大模型，也没有被认定为更强。

## 搜索选项

串行 PUCT 默认保留 64 次模拟，重复敏感状态使用配置中的 128 次。旧代码中硬编码 256 的行为已移除。网络自我对弈直接蒸馏实际访问次数；若明确选择调整循环目标，行动采样使用同一份调整结果。

`BatchedNeuralPUCT` 提供可选的单树多叶批量、完整输入与历史相关的推理缓存，以及显式按对局标识复用搜索树。推理缓存会在权重更新后失效，批量推理出错会撤销全部临时路径占用。

默认启用 CUDA Graph 推理，复用批量 1、2、4、8 的前向计算；权重版本改变会清除旧图，不支持捕获时自动回到常规前向。它保留串行 PUCT 的搜索次序。冻结测速的 1,206 次根结果比较中，落子与整组访问次数全部一致；16 局完整网络自我对弈的轨迹也全部一致，耗时从 86.8 秒降至 49.2 秒，约快 1.76 倍。单局 64 次搜索约从 283 毫秒降至 56 毫秒。这些数字仅适用于本次硬件、模型和预算。

其他选项分别改变计算开销或搜索路径。实际测速中缓存对多样局面没有稳定收益，因此默认关闭。多叶模式在 64 次模拟的开发对局中未证明更强，搜索树复用也未证明提高棋力，二者均保持可选。

## 独立评测

运行脚本前需要与训练入口一样设置原生模块和 Python 包路径：

```powershell
$env:PYTHONPATH="$PWD\build;$PWD\python"
python tools/evaluate_open_v4.py --part search --families 32 --opening-only --output reports/search_development.json
python tools/evaluate_open_v4.py --part trained --checkpoint runs/open_junqi_v4_repair_pilot/checkpoints/learner_000002.pt --families 32 --output reports/model_development.json
```

评测脚本只输出结果，不晋级模型。搜索实验比较固定模拟数，同时记录时间、推理批量和复用统计。原生教师使用其冻结预算；该比较不等于双方严格同毫秒的排行榜。

目前的修复与实测结果集中在 `reports/repair_20261003`。每次对局均保留布局、起始前缀、双方颜色、动作序列与终局原因，便于复查失败案例。

128 步训练后的模型对旧 150 轮模型的家族平均得分为 60.8%，95% 区间为 53.0%–68.6%；对强教师仍只有约 7%。教师配对对照未达到预先设置的非劣性门槛，因此出棋模型与冠军保留原版本，学习器保留全部有效更新。完整结论见 `reports/repair_20261003/REPORT_zh-CN.md`。
