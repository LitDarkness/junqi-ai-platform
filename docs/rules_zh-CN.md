# 中国军棋（明棋）完整规则说明

本文档是 `standard_open_v1` 的规范性人类可读说明。内容从本地 C++ 规则核、布阵校验器、规则测试及 SRS v1.1 交叉提取；发生冲突时，以本节“冲突消解”后的语义为准。

## 1. 对局目标与信息

- 两方分别为红方与黑方，红方先行，之后轮流走一手。
- 本平台是明棋：双方、裁判、GUI 与 AI 始终看见所有存活棋子的阵营和种类。
- 夺取对方军旗立即获胜；轮到一方时若没有任何合法着，该方失败。
- 重复三次、连续 200 ply 无吃子或达到 1000 ply 时判和。ply 指单方的一手。
- 终局优先级为：夺旗或无合法着胜负，高于最大步数、无吃子与重复判和。

## 2. 棋盘、坐标与地形

棋盘为 12 行 × 5 列，共 60 个格点。内部坐标为 `(row, col)`，行号 0—11、列号 0—4，索引为 `row * 5 + col`。红方布阵区是 0—5 行，黑方布阵区是 6—11 行。

### 2.1 大本营

大本营位于 `(0,1)`、`(0,3)`、`(11,1)`、`(11,3)`。己方军旗必须放在己方两个大本营之一。任何棋子一旦进入大本营便不能再移出。

### 2.2 行营

红方行营为 `(2,1)`、`(2,3)`、`(3,2)`、`(4,1)`、`(4,3)`；黑方行营为 `(7,1)`、`(7,3)`、`(8,2)`、`(9,1)`、`(9,3)`。

- 初始布阵时行营必须为空。
- 空行营可由有连线的相邻格进入。
- 行营与周围八方向中有连线的相邻格相通，因此允许相应的斜线一步移动。
- 行营内已有棋子时，该棋子受保护，敌方不能以行营为终点攻击它。
- 行营保护不限制其中棋子主动走出；但若目标是己方棋子仍不可进入。

### 2.3 铁路

铁路节点是：第 1、5、6、10 行的全部五格，以及第 1—10 行最左列和最右列。相邻铁路节点沿正交方向连接。

两军区域之间在第 5、6 行相接；`(5,1)—(6,1)` 与 `(5,3)—(6,3)` 被山界阻断，不能通过，其余实际连线按拓扑有效。

### 2.4 普通道路

非铁路长移动时，棋子只能沿棋盘邻接线走到相邻格。普通兵站之间是上下左右连接；与行营相邻时还存在上述斜线连接。不得进入己方棋子占据的格点。

## 3. 棋子种类与数量

每方 25 枚：司令 1、军长 1、师长 2、旅长 2、团长 2、营长 2、连长 3、排长 3、工兵 3、炸弹 2、地雷 3、军旗 1。

普通军阶从高到低为：司令、军长、师长、旅长、团长、营长、连长、排长、工兵。炸弹、地雷和军旗不参加普通军阶比较。

## 4. 初始布阵

每方有 6 × 5 共 30 个布阵槽，其中放置 25 枚棋子，五个行营保持为空。布阵必须同时满足：

- 棋子种类和数量与第 3 节完全一致；不能缺少、增加或使用未知类型。
- 军旗只能放在己方两个大本营之一。
- 三枚地雷只能放在己方最后两排：红方第 0—1 行，黑方第 10—11 行。
- 两枚炸弹不能放在最前排：红方第 5 行，黑方第 6 行。
- 五个己方行营必须为空。

除这些限制外，其余棋子可以自由布置。随机布阵器也必须生成满足同一校验器的布局。

## 5. 行棋规则

### 5.1 不可移动棋子

地雷和军旗永远不能主动移动。任何位于大本营内的棋子也不能主动移动。

### 5.2 道路移动

可移动棋子可沿一条普通邻接线走一格。目标为空时直接占据；目标为敌方棋子时发生战斗；目标为己方棋子或受保护的敌方行营时非法。

### 5.3 非工兵铁路移动

非工兵位于铁路上时，可沿同一行或同一列的连续铁路直线移动任意距离。中间每一格必须为空，不能跨越棋子、铁路断点或山界。遇到第一枚棋子时，只能在其为可攻击敌子时以该格为终点，不能继续越过，也不能在铁路上转弯。

### 5.4 工兵铁路移动

工兵位于铁路上时，可沿连通铁路移动并在交叉点转弯。路径中间格必须为空。搜索到敌子所在铁路格时可以攻击该格，但不能穿过它；己方棋子和受保护行营同样阻断路径。

### 5.5 合法着的一致性

合法着集合直接由规则核生成，不以遍历全部 3600 个动作再试错作为正式算法。动作编码是 `from * 60 + to`，编码空间中的绝大多数动作通常非法。输出顺序按起点索引、再按生成器确定的目标顺序保持确定。

## 6. 战斗规则

攻击者进入敌子所在格时按下列顺序裁决：

1. 防守方是军旗：攻击方夺旗并立即获胜，攻击棋子进入军旗格。
2. 任一方是炸弹：双方同时移除；因此炸弹攻击地雷或地雷被炸弹攻击也同归于尽。
3. 工兵攻击地雷：地雷移除，工兵进入目标格并存活。
4. 其他棋子攻击地雷：攻击者移除，地雷存活。
5. 其余情况比较普通军阶：高者存活；攻击方胜时进入目标格，防守方胜时留在原格；同级双方移除。

军旗和地雷本身不能主动攻击，因为它们不可移动。战斗只影响参与战斗的棋子，不会产生连锁战斗。

## 7. 回合、记录与终局

- 合法的一手无论是否发生战斗都只增加一次 ply；夺旗这一手也计数一次。
- 非终局手完成后切换行动方。终局状态不再接受后续动作。
- 完整局面键至少包含 60 格棋子、阵营和行动方；重复判定使用该键。
- 吃子包括一方或双方因战斗被移除；发生战斗即重置无吃子计数，纯移动使计数加一。
- 三次重复：同一完整局面（包括行动方）第三次出现时判和。
- 无吃子：连续 200 ply 未发生战斗时判和。
- 最大步数：完成第 1000 ply 且此前无决定性胜负时判和。
- 终局原因码为 `FLAG_CAPTURE`、`NO_LEGAL_MOVE`、`REPETITION`、`NO_CAPTURE_LIMIT` 或 `MAX_PLY`。

## 8. 非法动作与状态不变性

下列情况非法：游戏已结束、坐标越界、起终点相同、起点为空、不是行动方棋子、棋子不可移动、从大本营移出、目标为己子、攻击受保护行营、没有棋盘连线、铁路不连续、铁路未成直线（非工兵）、路径被阻挡。

非法动作必须返回稳定原因码或抛出明确异常，且不得改变棋盘、行动方、ply、历史、哈希或终局状态。

## 9. 冲突消解与实现保证

本地旧 README 把环境描述为暗棋，并保留“司令死亡后亮旗”字段；SRS v1.1 明确要求明棋。本配置统一采用全信息观测，亮旗状态仅作为旧记录兼容字段，不影响可见性。

旧实现将“全歼”单列为胜因，而 SRS 默认胜因是夺旗或对手无合法着。全歼必然使对手无合法着，因此统一记录为 `NO_LEGAL_MOVE`，不增加第三种规则语义。

旧 C++ 对普通战斗在结算器中计步，而夺旗提前返回导致夺旗手不计步；现已保证夺旗手也恰好计一次。

SRS 要求拓扑数据化；当前 C++ 仍以预计算后的固定拓扑构造标准棋盘，配置文件锁定为 `standard_5x12_v1`。在支持自定义拓扑前，不允许用同一 profile id 改变任何坐标或连线。

规则配置的规范 JSON 按键排序、无多余空白后计算 SHA-256。对局记录必须同时保存 profile id、SHA-256 和完整规则对象，避免只有哈希而无法还原规则。
